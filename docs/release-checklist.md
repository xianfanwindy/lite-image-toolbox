# 个人主体发布清单

当前环境缺少个人小程序 AppID、WeChat DevTools、Android 真机和 iPhone 真机，因此下面所有项目均保持未勾选。只有完成对应操作并保留实际结果后，才能逐项勾选；Node.js 测试或模拟器结果不能替代开发者工具编译和真机验证。

1. [ ] 注册微信小程序账号，并完成个人主体实名认证。
2. [ ] 按微信公众平台当期要求完成小程序备案、主体扫码确认和所需资料提交。
3. [ ] 获取个人小程序 AppID；只在本地把 `project.config.json` 的 `touristappid` 临时替换为真实 AppID，不把真实 AppID 提交到仓库。
4. [ ] 在微信后台填写并确认小程序名称、服务类目、简介和实际服务内容，确保与“轻图工具箱”的四项本地图片功能一致。
5. [ ] 根据 [隐私保护指引](privacy-guide.md) 和实际发布代码配置用户隐私保护指引，确认相册保存用途与 `app.json` 的权限说明一致。
6. [ ] 从干净检出的仓库根目录导入 WeChat DevTools，运行 `npm test`，完成编译和开发者工具代码质量检查，确认没有真实 AppID、广告 unit ID、密钥或个人信息进入提交。
7. [ ] 在图片压缩、尺寸调整、九宫格切图和文字水印页面逐页验证普通 JPG、透明 PNG、超大图片、极端横图、极端竖图、取消选图、拒绝相册权限后恢复以及连续重复处理。
8. [ ] 在至少一台 Android 真机上验证选图、处理、预览、权限拒绝与恢复、保存结果和连续操作。
9. [ ] 在至少一台 iPhone 真机上完成与 Android 相同的验证。
10. [ ] 上传体验版，添加体验成员，并使用体验成员账号重新验证四个工具的完整闭环。
11. [ ] 如果尚未满足或开通微信流量主资格，保持 `config/ads.js` 的两个 Banner unit ID 为空，并确认页面没有广告空白占位。
12. [ ] 满足并开通流量主资格后，只临时配置 `homeBannerUnitId` 和 `resultBannerUnitId` 两个 Banner unit ID；验证首页和结果页展示正常、加载失败时隐藏且核心功能不受影响，上传完成后恢复空值且不提交真实 ID。
13. [ ] 上传审核版本，按真实功能填写版本说明、隐私说明和审核操作路径，再提交微信审核。
14. [ ] 审核通过后发布；首周检查崩溃、选图与相册权限异常、图片处理失败和 Banner 广告异常，并只针对真实问题安排修复。

Android 或 iPhone 任一平台尚未通过真机验证时，本清单都不能视为完成。WeChat DevTools 模拟器只能用于辅助检查，不能替代任何一个真机平台。
