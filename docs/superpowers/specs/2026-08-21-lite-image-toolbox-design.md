# 轻图工具箱设计规格

日期：2026-08-21

状态：已确认

目标平台：微信小程序（个人主体）

## 1. 目标

开发一款面向个人用户的轻量图片处理微信小程序，以低维护、快速上线为首要目标。首版只提供四个完全在手机本地运行的图片工具，不使用服务器、数据库、用户账号、外部 API 或微信支付。

交付目标不是停留在静态原型，而是形成取得 AppID 后即可导入微信开发者工具、上传体验版并进入审核准备流程的完整版本。

## 2. 产品定位

- 产品名称：轻图工具箱
- 上线主体：个人
- 收入方式：微信流量主普通广告
- 首版原则：核心功能不依赖广告，未开通流量主时仍可完整使用
- 视觉方向：A 方案“清爽可信”，采用白色背景、绿色强调色和直接的信息层级
- 隐私承诺：图片只在用户设备本地处理，不上传服务器

## 3. 首版范围

首版包含以下四个工具：

1. 图片压缩
2. 图片尺寸调整
3. 九宫格切图
4. 图片文字水印

首版明确不包含：

- 长图拼接
- 图片格式转换
- Logo 或在线水印素材库
- 登录、会员、云同步和使用历史
- 微信支付、订阅或激活码
- 激励视频、插屏广告和强制广告
- 后端服务、数据库、云函数和外部 API
- 在线图库、用户生成内容社区和运营后台

## 4. 实施路线

采用“精简复用”方式，以 MIT License 的 `LittleWhite1995/tools-applet` 为实现参考和代码底座。实施时保留原项目许可证及必要版权信息，实际删除无关页面、依赖和配置，而不是只隐藏入口。

选择该路线的原因：

- 四项核心图片能力已有可参考实现，可缩短首版开发周期。
- 原项目采用原生微信小程序技术栈，且多数处理在本地完成。
- 相比完整 Fork，精简后包体、权限范围和维护面更小。
- 相比从零实现，可减少 Canvas、图片保存和设备兼容方面的重复工作。

正式实施前应记录所复用上游仓库的具体 commit，并逐项确认复用文件的许可证来源。

## 5. 技术架构

项目采用原生微信小程序架构，分为五个边界清晰的部分：

### 5.1 首页

- 展示四个工具入口。
- 展示“图片仅在本机处理”的隐私提示。
- 可选渲染首页底部广告位。
- 不请求登录，不读取或展示个人资料。

### 5.2 工具模块

四个工具各自拥有独立页面和参数状态。一个工具的处理失败不得影响其他工具。

- 图片压缩：质量滑杆，默认 80%，展示处理前后文件大小。JPG 按质量参数导出；带透明通道的 PNG 保持透明，不承诺仅靠质量参数显著减小体积。
- 尺寸调整：提供原图、50% 和自定义宽高；默认锁定宽高比，并保持 PNG 透明通道。
- 九宫格切图：先进行正方形裁剪，再生成并按正确顺序保存九张图片。
- 图片水印：首版只支持文字、黑白两种文字颜色、五个固定位置（左上、右上、居中、左下、右下）和透明度，不支持在线 Logo 素材。

### 5.3 公共图片层

统一封装以下能力：

- 从相册选择图片或拍照
- 读取图片尺寸和基础信息
- Canvas 绘制与导出
- 处理结果预览
- 保存到系统相册
- 临时文件生命周期管理
- 图片尺寸和内存边界检查

工具页面只传入参数，不各自重复实现权限和文件管理逻辑。

### 5.4 广告配置层

- 广告配置独立于工具业务逻辑。
- 默认关闭，不内置真实广告单元 ID。
- 首版只支持首页底部和结果页两个 Banner 广告位置。
- 未配置广告 ID 或广告加载失败时，不渲染广告容器。
- 广告不得成为处理、预览或保存图片的前置条件。

### 5.5 隐私与权限层

- 不上传、收集或保存用户图片。
- 不采集手机号、昵称、头像、位置和设备标识。
- 只声明选择图片、拍照和保存相册实际需要的能力。
- 权限被拒后提供解释和“前往设置”入口，不反复弹窗。
- 隐私声明必须与真实代码和微信后台配置一致。

## 6. 用户流程

四个工具共享统一主流程：

1. 用户从首页选择工具。
2. 用户从相册选图或拍照。
3. 页面只显示当前工具需要的参数。
4. 用户执行处理并查看结果预览。
5. 用户授权后将结果保存到相册。
6. 若已配置流量主，结果页保存按钮下方可展示普通广告。

统一流程使用户只需学习一次操作方式，并降低页面间的不一致。

## 7. 异常处理

- 用户取消选图：留在当前页面，不显示错误提示。
- 图片尺寸或内存开销过大：明确提示降低尺寸或重新选择，不尝试无限重试。
- Canvas 处理失败：不生成空文件，保留原参数供用户重试。
- 保存权限被拒：说明用途并提供前往系统设置的入口。
- 临时文件失效：提示用户重新处理。
- 广告加载失败：静默隐藏广告，不影响任何核心功能。
- 连续处理：每次开始前释放上一轮不再使用的临时状态，避免内存累积。

## 8. 视觉设计

首页使用 A 方案“清爽可信”：

- 白色主背景和浅绿色辅助区域
- 微信绿方向的主操作色
- 四个工具采用两列卡片布局
- 顶部强调“安全、快速、无需上传”
- 广告位未启用时不保留空白占位
- 页面优先保证文字清晰、按钮可点击范围和系统字体兼容性

视觉设计不依赖在线字体、在线图标或远程图片资源。

## 9. 测试策略

### 9.1 逻辑测试

- 尺寸缩放和宽高比计算
- 九宫格裁剪坐标和输出顺序
- 水印位置、边距和透明度换算
- 广告配置开关和空 ID 行为

### 9.2 页面与异常测试

每个工具至少覆盖：

- 普通 JPG
- 透明 PNG
- 超大图片
- 极端横图和极端竖图
- 取消选图
- 保存权限拒绝后恢复
- 连续多次处理
- 页面返回后重新进入
- 广告未配置和广告加载失败

### 9.3 环境验证

- 微信开发者工具能够从干净检出状态导入、构建和编译。
- 至少完成一台 Android 和一台 iPhone 真机验证。
- 如果提交审核前只有单一平台设备，另一平台必须保留为发布阻断项，不能用模拟器结果替代。

## 10. 验收标准

以下条件全部满足才视为首版完成：

1. 四个工具均能完成选图、处理、预览和保存闭环。
2. 所有图片处理均在本地完成，核心流程中不存在图片上传请求。
3. 未配置广告时无空白广告区域；广告失败不影响工具功能。
4. 权限拒绝、图片过大和处理失败均有可恢复路径。
5. 干净检出后可按文档导入微信开发者工具并成功编译。
6. Android 和 iPhone 真机验证通过。
7. README、配置说明、隐私声明与真实行为一致。
8. 提供个人小程序账号注册、备案、AppID 配置、体验版上传、隐私设置和流量主开通清单。
9. 源码不包含真实 AppID、广告单元 ID、密钥或个人信息。
10. 取得 AppID 后，项目达到可上传体验版并准备提交审核的状态。

## 11. 发布与维护边界

用户本人负责必须由账号主体完成的操作，包括注册、实名、扫码确认、备案资料提交和最终审核提交。开发工作负责提供可验证源码、配置位置、操作清单和审核问题修复支持。

上线后的预期维护主要包括：

- 定期检查微信基础库兼容性和审核规则变化
- 查看广告位异常和用户反馈
- 在新系统版本上抽查相册选择与保存权限
- 修复真实出现的兼容问题

首版不承诺固定收入。广告收益取决于真实用户量、留存、广告填充和平台规则。
